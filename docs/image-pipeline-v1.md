# 图片安全处理与预览管线 v1

本文记录任务 4 已实现的图片输入边界、受管输出和生命周期。图片管线完全
在本地运行，不上传图片，不执行云端主体识别。

## 图像库与许可证

- 图像库：`SkiaSharp 4.150.1`。
- 许可证：MIT。
- 选择原因：支持 .NET 8 和 Windows 桌面，能够解码 PNG、JPEG、WebP，
  提供 EXIF 方向信息，并能重新编码 WebP。
- 发布影响：包包含 Skia Windows 原生资源，也会带来额外便携包体积。
  第三方 Notices、原生二进制哈希和包体积由各版本发布验收记录汇总验证。

没有使用许可为 Six Labors Split License 的 ImageSharp，也没有复制参考
项目的图片处理源码或测试素材。

## 输入边界

- 只接受真实内容为 PNG、JPEG 或 WebP 的静态图片。
- 根据文件头和解码器报告双重确认格式，不信任文件扩展名。
- 扩展名与内容不一致时按真实内容处理，并在结果中返回真实格式。
- SVG、GIF、HTML、ICO、PSD、畸形内容和多帧动画图片均拒绝。
- 原始输入最多 100 MiB。
- 单边最多 16384 像素。
- 总像素最多 5000 万。
- 先读取编码宽高并检查上限，通过后才分配完整 BGRA 解码缓冲。
- 解码结果必须完整成功；不接受截断图片的部分解码结果。
- 接近文件或像素上限的复杂图片可能在读取、完整 BGRA 解码、方向修正和
  WebP 重编码期间占用数百 MiB 临时内存；内存不足时安全失败，不提交半成品。

源文件名只用于输入校验，不参与目录或输出文件名生成。

## 方向和元数据

JPEG 的 EXIF 方向在像素层应用到输出。重新编码只使用已解码像素，不复制
原始 EXIF、GPS、ICC profile、注释或其他应用数据。因此运行时副本、编辑器
预览和卡片缩略图均不包含原始定位或相机元数据。

## 受管输出

所有输出固定为有损 WebP，质量参数为 `90`：

```text
themes/<theme-uuid>/background-<output-sha256>.webp
cache/previews/<output-sha256>.webp
cache/thumbnails/<output-sha256>.webp
```

- 运行时背景：修正方向后的原始像素尺寸。
- 编辑器预览：在 `1600 × 1000` 边界内等比缩放，不放大小图。
- 卡片缩略图：在 `480 × 320` 边界内等比缩放，不放大小图。
- 每个重新编码后的受管图片最多 32 MiB；超过时拒绝导入，不允许出现
  “保存成功但运行时无法应用”的不一致状态。

三个产物分别记录相对 DataRoot 的路径、尺寸、长度和 SHA-256。源文件也
计算 SHA-256。预览与缩略图使用完整输出指纹命名；已有文件只有在重新计算
哈希一致时才复用，复用结果会提供重复图片建议。

## 暂存、提交和回滚

每次处理使用独立目录：

```text
runtime/image-imports/<operation-id>/
```

完整解码和三个产物编码成功后，才从暂存目录移动到最终路径。最终文件不
覆盖已有路径；并发命中必须验证哈希。取消或失败只清理本次创建的暂存文件
和本次新建的最终文件，不处理既有用户文件。

`ThemeImageImportService.ImportNewAsync` 只用于新主题：

1. 拒绝已存在的目标主题目录。
2. 调用图片管线生成受管资源。
3. 将主题 `art.file` 替换为受管运行时背景文件名。
4. 将卡片缩略图相对路径交给 SQLite 仓储。
5. 仓储事务失败时移除本次新建的主题 JSON 和运行时资源，不留下数据库
   记录或有效主题目录；全局指纹缓存可以保留供后续安全复用。

## 自适应建议

管线只返回建议，不修改用户已确认的颜色、焦点或主题设置：

- 超宽：宽高比 `>= 2.1`。
- 宽屏：`>= 1.6`。
- 横图：`> 1.1`。
- 方图：`0.9..1.1`。
- 竖图：`< 0.9`。

超宽/宽屏建议 `banner`，竖图建议 `off`，其他建议 `ambient`。这些值是
编辑器建议契约，不改变任务 3 已冻结的 Theme Schema 枚举。

第一版没有自动主体识别或主色提取；焦点和颜色继续由用户手动确认。
