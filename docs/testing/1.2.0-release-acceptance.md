# 1.2.0 清理、轻量化与发布验收

## 实施范围

- 维护基线升级为 `1.2.0`，继续支持 Windows 10/11 x64、.NET 8 WPF、内置 Node.js 24.18.0、自包含便携目录和 ZIP。
- Desktop 与 Agent 仍分别执行 self-contained publish；最终便携包通过 Schema v1 `agent-bundle-manifest.json` 复用相同运行时文件。
- 稳定 Agent 安装改为严格清单驱动，校验路径、大小、SHA-256、重解析点、重复目标和 Schema 后，再以暂存目录原子切换。
- GitHub Actions 支持手动私有预演；精确版本标签触发 Draft Release，并只上传产品 ZIP、`SHA256SUMS.txt` 和 `release-manifest.json`。

## 本地验证

- 使用固定 `.NET SDK 8.0.423` 执行 `.\build.ps1 -Configuration Release`：0 警告、0 错误。
- .NET 测试 234 项通过；2 项需要显式真实持久化授权的 Integration 测试跳过。
- Node 测试 26 项通过；Agent self-test 和 Injector self-test 通过。
- Agent bundle 回归覆盖共享文件重建、未知 Schema、路径逃逸、重复目标、哈希不符、损坏稳定版本、相同指纹复用、取消后无暂存残留和重解析点来源拒绝。
- WPF 测试宿主只加载产品资源字典，不再实例化生产 `App`，因此测试期间不会启动真实主窗口或显示缺少 Injector 的误导提示。
- 最终包包含 302 个文件，解压总大小为 261,811,252 字节。
- Agent 与 Desktop 共享并从 `agent/` 去重的运行时为 74,080,584 字节；`agent/` 中只保留独有内容与安装清单。
- ZIP 大小为 109,736,514 字节：高于 100,000,000 字节首选目标，因此输出警告；低于 120,000,000 字节硬上限，因此通过发布门禁。
- ZIP SHA-256：`9df24400074347e59f2b032f10525f48324da65698f07f3e71ec41d63731fc6b`。
- 主程序与 Agent 均为 `NotSigned`；发布文档已披露未知发布者提示。
- 最终包逐项复核 196 个 Agent 清单源文件：缺失 0、大小或 SHA-256 不符 0。
- 禁止内容检查未发现 PDB、测试夹具、日志、数据库、截图、凭证或私人用户数据；卫星资源只保留 `zh-Hans`。
- 最终 ZIP 已解压到同时含中文和空格的独立路径；严格按 manifest 重建的
  Agent self-test 与随包 Injector self-test 均返回 Schema/协议 v1 `ok`。
- 从该路径真实启动 `CodexThemeManager.exe` 后主窗口正常显示，UI 自动化检查
  299 个可访问名称，未发现“启动失败”“随包 Injector Runtime 不完整”或
  “操作失败”，正常关闭退出码为 0。
- 真实启动曾发现应用目录末尾分隔符导致随包定位器向上遍历空引用；修复为统一
  规范化目录路径并增加回归测试。Desktop 测试程序集同时禁用并行，避免共享
  WPF Dispatcher 的异步测试相互穿插导致色板测试间歇失败。
- 原始图片输入上限已从 16 MiB 调整为 100 MiB，单边 16384 像素和总计
  5000 万像素限制保持不变。重新编码后的受管图片上限为 32 MiB，Renderer
  JSON 标准输入上限协调为 48 MiB；主题包上限为 40 MiB，解压总量继续限制
  为 64 MiB。对应 Storage、CodexAdapter 和 Node 回归及完整 Release 构建通过。
- 维护者已在另一台 Windows 机器上人工确认应用可以启动并运行；该机器并非
  完全干净环境，因此这项结果只作为跨机器可运行性证据，不能替代无预装
  .NET/Node 的干净 Windows/VM 验收。具体 Windows 版本与预装 Runtime 状态
  `To be confirmed`。

## 本机归档清理

- `1.0.1`、`1.1.0` 至 `1.1.6`、`1.1.8` 至 `1.1.10` 共 11 个发布目录已移入 Windows 回收站，没有永久删除。
- 清理目标共 33 个文件、1,665,543,233 字节；项目发布目录当前只保留 `1.1.7` 和 `1.2.0`。

## 公开仓库卫生检查

- 三个失效的本机交接快照共 708,075 字节，已在确认普通文件、大小和
  SHA-256 后移入 D 盘回收站；对应 `$I` 元数据和 `$R` 数据项存在，源路径已消失。
- `.gitignore` 已补充根目录交接快照、环境文件、签名材料、私钥、日志、数据库
  和操作系统临时文件规则，同时保留既有生成物与固定 Node Runtime 规则。
- README 已收敛为面向 Windows 用户的公开下载首页，并明确便携资产、源码归档、
  未签名状态和非官方产品边界。
- 已增加安全报告基线、独立 CI 与最小权限 Draft Release 流程。普通 push 不创建
  tag 或 Release，版本 tag 始终由维护者人工创建。
- 已使用 actionlint `1.7.12` 检查两个 GitHub Actions workflow，未发现语法或语义错误。
- 已使用 gitleaks `8.30.1` 扫描当前工作树和全部两个历史提交；唯一命中是
  `Icons.xaml` 中的 `LucideTrash2Geometry` WPF 资源键，人工确认不是凭证。
- 已使用 TruffleHog `3.96.0` 在禁用外部凭证验证的模式下交叉检查；当前源码的
  两个未验证 URI 命中均来自安全测试中故意构造的带伪造凭证回环 URI 拒绝样例，
  全部两个历史提交中的命中也仅是同一组测试夹具；没有已验证凭证命中。
- 结合工具扫描和人工复核，未发现真实邮箱、私钥、GitHub/OpenAI/AWS
  高置信度凭证或个人机器路径。
- Gitleaks 使用仓库内的精确 allowlist，只允许 `Icons.xaml` 中已人工确认的
  `LucideTrash2Geometry` 资源键误报；不豁免整个文件或通用密钥规则。
- TruffleHog 的两个当前源码命中分别来自
  `runtime/injector/security.test.mjs` 和
  `tests/CodexAdapter.Tests/InspectorEndpointPolicyTests.cs` 中故意构造的伪凭证
  回环 URI，用于验证拒绝策略；未设置宽泛排除。
- 本机 DataRoot 中用于测试的三张第三方游戏壁纸及对应主题不属于可再分发素材。
  打包和 Release workflow 会按主题名称、文件类型与图片 SHA-256 阻断它们进入
  发布资产，同时不会移动、删除或修改本机主题。
- 首次 GitHub 发布资产已按最终源码重新生成；本文件顶部记录的大小、哈希和
  二进制结论对应当前本地候选。
