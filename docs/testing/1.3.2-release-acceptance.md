# 1.3.2 Inspector 生命周期修复发布验收

## 变更范围

- Inspector 开启流程先向已校验的 Codex 主进程发送调试信号，再使用 Node 本地 TCP 探测等待端口可达，避免缓慢的 Windows 端口查询耗尽开启门限。
- 端口可达后仍通过 Windows 端口 API 校验回环监听地址与 OwningProcess，读取 Inspector 元数据前不放宽信任边界。
- Inspector 关闭等待先确认 TCP 不可达并完成稳定等待，再执行最终权威端口查询；操作失败后的清理不再因端口已关闭而制造次生元数据错误。
- 新增独立生命周期模块与回归测试，并把该模块纳入构建测试和便携包生产文件清单。
- 设置页按钮文案由“选择 Codex EXE”改为“选择 Codex 程序”；命令、样式和交互行为未改变。
- 主题 Schema、运行时 CSS、持久化配置格式、自更新 API 与三个 Release 资产契约均未改变。

## 未覆盖风险

- 当前没有可用的干净 Windows 用户或 VM；无预装 .NET/Node 环境的启动与完整交互不得写为通过。
- 当前没有有效 Microsoft Defender 服务、实时保护和病毒库；维护者明确选择不在本机恢复 Defender，ZIP 与展开目录的有效病毒扫描不得写为通过。
- 真实 updater 进程在目录切换期间被终止以及断电边界未覆盖；自动化回滚测试不能替代上述证据。
- 2026-09-10，维护者明确接受上述三项仅针对 `v1.3.2` 的发布风险，并授权创建及 squash 合并发布 PR、推送 `v1.3.2` tag 生成 Draft Release。该接受不代表门禁通过、不关闭风险，也不适用于后续版本；Draft 与最终公开页面必须继续披露。

## 边界

- `v1.3.1` 已具备更新器；只有公开、稳定、非 prerelease、Latest 的 `v1.3.2` 才会被程序内更新发现。
- Draft、构建成功或当前主机验收均不能替代干净 Windows、有效病毒扫描或公开端点更新验收。
- Codex 不自动公开 Release，不覆盖既有 tag，不 force-push，也不把未执行项记录为通过。
