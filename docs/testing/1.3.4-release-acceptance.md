# 1.3.4 Codex 26.911 Inspector 稳定性修复验收

## 变更范围

- 持久化 Agent 对同一 Codex 实例的成功状态先执行无侵入身份短路，至少 15 分钟内不再打开 Inspector；旧配置中的更短复核值在运行时提升到该安全下限。
- 到达复核间隔后只执行一次 Renderer 状态检查，不再重复构建级能力探测。
- 当前 PID 的 Inspector 查询、应用或运行时标记验证失败后按 PID、创建时间和 EXE SHA-256 熔断；后续轮询 fail-closed，不再重复打开 Inspector。
- 状态 Schema 保持版本 1，并以可选字段兼容既有 `state.json`；主题 Schema、运行时 CSS、更新资产契约和用户数据格式均未改变。
- 稳定版本更新为 `1.3.4`，并增加 `1.3.3 → 1.3.4` 以及 `1.3.4-rc.1 → 1.3.4` 的 SemVer 顺序回归和稳定更新发现回归。

## 问题证据与判断

- 2026-09-17 在 Store Codex `26.911.7940.0` 上观察到多次 browser 主进程异常；ProcDump 记录 `0x80000003` 与 `chrome.dll`，但终止转储缺少原始异常上下文，因此不能把 Theme Studio 写为已确认唯一根因。
- 源码审计确认 `1.3.3` 在同一实例安全间隔判断之前执行能力探测，并在复核时再次打开 Inspector；这会把配置为 60 秒的复核放大为持续 Inspector 生命周期风险。
- 本版本减少 Inspector 频率并为当前失败实例熔断，目标是消除 Theme Studio 可控的高频触发条件，而不是宣称修复第三方 Electron 内部崩溃根因。

## 未覆盖风险

- 当前没有可用的干净 Windows 用户或 VM；无预装 .NET/Node 环境的启动与完整交互不得写为通过。
- 当前没有有效 Microsoft Defender 服务、实时保护和病毒库；ZIP 与展开目录的有效病毒扫描不得写为通过。
- 真实 updater 在目录切换期间被终止以及断电边界未覆盖；自动化回滚测试不能替代上述证据。
- 上述缺失项必须在 README、风险登记、验收记录和 Release Notes 中继续披露；公开前的本版本风险接受：`To be confirmed`。

## 边界

- `1.3.3` 已具备更新器；只有公开、稳定、非 prerelease 且为 Latest 的 `v1.3.4` 才会被程序内自动检查发现，下载和安装仍由用户主动触发。
- `1.3.4-rc.1` 只作为私有 Artifact 和当前主机候选验证包，不创建面向普通用户的 prerelease Release。
- Draft、构建成功或当前主机验收均不能替代干净 Windows、有效病毒扫描或公开端点更新验收。
- Codex 不 force-push、不覆盖既有 tag，也不把未执行项记录为通过。
