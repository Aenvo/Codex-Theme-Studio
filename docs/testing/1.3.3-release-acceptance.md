# 1.3.3 发布门禁稳定性修复验收

## 变更范围

- `QualificationCycle_UsesDedicatedLongerDeadline` 保留“资格闭环可超过普通操作门限”的原验证语义，把测试专用普通门限从 100 ms 扩大到 500 ms、资格门限从 500 ms 扩大到 5 s，并把三次模拟渲染延迟从 45 ms 扩大到 300 ms。
- 成功断言附带结构化诊断码，后续失败时可直接区分资格闭环超时与其他错误。
- 生产代码、生产超时、Inspector 安全边界、主题 Schema、运行时 CSS、持久化配置和更新资产契约均未改变。
- 版本基线更新为 `1.3.3`，并增加 `1.3.2 → 1.3.3` 的 SemVer 顺序回归。

## 失败证据与判断

- `v1.3.2` 的 PR CI、`main` CI、本机正式打包与连续 40 次定向测试均通过；tag workflow `34424738768` 的两次运行却在同一测试的成功断言失败，耗时分别约 1 秒和 713 ms。
- 原测试在三次 45 ms 人工延迟之外只给资格闭环 500 ms 总墙钟预算；GitHub runner 调度开销足以耗尽余量。现有证据支持“测试时间尺度抖动”为最可能原因，但未加入逐阶段计时，因此不把 runner 内的精确延迟来源写为已确认。
- 新时间尺度要求约 900 ms 的模拟工作超过 500 ms 普通操作门限，同时远低于 5 s 资格门限，保留区分能力并提供更稳定的调度余量。

- 当前没有可用的干净 Windows 用户或 VM；无预装 .NET/Node 环境的启动与完整交互不得写为通过。
- 当前没有有效 Microsoft Defender 服务、实时保护和病毒库；维护者明确选择不在本机恢复 Defender，ZIP 与展开目录的有效病毒扫描不得写为通过。
- 真实 updater 进程在目录切换期间被终止以及断电边界未覆盖；自动化回滚测试不能替代上述证据。

## 边界

- `v1.3.1` 已具备更新器；只有公开、稳定、非 prerelease 且为 Latest 的 `v1.3.3` 才会被程序内更新发现。
- `v1.3.2` tag 保留为失败证据，不删除、不移动、不覆盖；该版本没有 Release 资产。
- Draft、构建成功或当前主机验收均不能替代干净 Windows、有效病毒扫描或公开端点更新验收。
